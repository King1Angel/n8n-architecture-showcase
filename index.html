Decisiones de Arquitectura y Resolución de Retos Complejos

Patrones aplicados para garantizar alta disponibilidad, resiliencia ante límites de API y procesamiento de datos heterogéneos.

Resiliencia & Cuotas de API

Manejo de Saturación y Retries Exponenciales

Durante picos de alta demanda, las APIs de LLM pueden arrojar respuestas transitorias 503 Service Unavailable o 429 Rate Limit. Se configuró una política de resiliencia con 3 reintentos automáticos y backoff exponencial (2500ms) en los nodos de Gemini y el Agente, asegurando que las ráfagas no causen interrupciones en el chat del usuario.

// Política de Reintentos en Nodos Críticos const retryPolicy = { retryOnFail: true, maxTries: 3, waitBetweenTries: 2500 // ms };
Desacoplamiento & Datos Binarios

Arquitectura de Subflujo para Hojas de Cálculo

Los agentes de lenguaje nativos operan en texto plano y suelen fallar al leer archivos binarios de Excel (`.xlsx`). La solución consistió en crear un **micro-workflow dedicado (`Drive - Leer Excel Helper`)** que actúa como puente: descarga el binario auténtico desde Drive, lo procesa con el motor nativo de n8n y retorna al agente un payload JSON optimizado para la ventana de contexto.

// Subflujo Desacoplado: Webhook -> Drive API -> Spreadsheet Node POST /webhook/leer-excel-drive → DriveDownload(alt=media) → SpreadsheetParser(.xlsx/.csv) → ContextLimiter(sampleRows: 250)
DevOps & Observabilidad

Patrón Agente Sanador (Self-Healing DevOps)

En lugar de depender de alertas pasivas, se diseñó un flujo de supervisión que detecta ejecuciones fallidas, lee la causa raíz directamente desde SQLite / API de n8n y permite al Agente Sanador aplicar parches a parámetros de nodos o reiniciar servicios en vivo.

// Ciclo Cerrado de Sanación ErrorTrigger → ErrorNotifier → DevOpsAgent(Auditar, Parchear) → Auto-fix aplicada → Re-activación vía API
Seguridad y UX Conversacional

Protocolo Human-in-the-Loop para Acciones Críticas

Para mitigar riesgos de alucinaciones en el envío de correos corporativos o modificaciones de calendario, el agente implementa un protocolo estricto: presenta primero una propuesta estructurada en 4 bloques con tono profesional y requiere una confirmación afirmativa explícita antes de invocar la herramienta de despacho.

// Protocolo Estricto de Confirmación Previa Prompt Solicitud → Formular Borrador → Presentar en Telegram → ¿Aprobado? [SI → EnviarCorreo() | NO → Ajustar]
